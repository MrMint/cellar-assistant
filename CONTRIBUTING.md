# Contributing

Thanks for taking an interest. Issues and pull requests are both welcome.

This is a hobby-scale project maintained in spare time — reviews may take a
while, and a feature that doesn't fit may be declined. Opening an issue before
starting anything large will save you effort.

**Security problems go to [`SECURITY.md`](SECURITY.md), not to a public issue.**

## Before you start

Get a working stack first — [`README.md`](README.md) has the whole path, but
the short version is:

```bash
bun install
bun run dev:bootstrap    # infra, schema, both backend apps, seed data
bun run dev              # the Next dev server, in its own terminal
```

If anything looks wrong, `bun run dev:doctor` names every known silent failure
mode, and `bun run dev:doctor --fix` repairs the ones it can.

Two prerequisites are exact, not approximate: **Node 24.14.0** (`.nvmrc`) and
**Bun 1.4.2** (`packageManager`). A mismatched Node is the single most common
cause of a red test suite that looks like real failures — some tests run
TypeScript through Node's native type stripping and fail as ordinary assertion
errors under an older runtime. Check `node -v` and `bun --version` before you
believe a broken suite.

This project uses **bun**, not npm, pnpm or yarn. There is one `bun.lock` at the
root and the workspace globs live in the root `package.json`.

## Making a change

1. Branch off `main`.
2. Make the change.
3. Run the checks below.
4. Open a pull request, filling in the template.

### Checks

Run these before pushing. CI runs the same things, so a local failure is a
guaranteed red build:

```bash
bun run typecheck   # tsc across the graph; GraphQL codegen runs first
bun run check       # Biome lint + format
bun run test        # unit + integration suites
```

`bun run check:fix` applies the safe fixes automatically.

The Playwright suite is slower and needs a running stack:

```bash
bun run stack:up    # shared stack; serves the client on 3003
bun run test:e2e
```

If you'd rather run it against your own dev server, use
`E2E_BASE_URL=http://localhost:3000 bun run test:e2e` with `bun run dev` up.

### Commits

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/)
— `feat:`, `fix:`, `chore:`, `docs:`, and so on, with an optional scope like
`feat(cellars):`. Releases and the changelog are generated from them by
release-please, so the prefix decides the version bump. Don't edit
`CHANGELOG.md` by hand.

## Conventions

The authoritative developer guide is [`AGENTS.md`](AGENTS.md). It is written
for both humans and coding agents, and it records the traps that have already
cost real time. Read it before a first substantial change. The short version:

- **Formatting and linting is Biome.** Not ESLint, not Prettier — there is no
  config for either.
- **Avoid non-null assertions (`!`).** Use `??` instead.
- **Use `satisfies`** to type-check without widening.
- **UI is MUI Joy.** Prefer Joy components and its design tokens; prefer the
  `sx` prop over stylesheets; reach for Emotion only when Joy genuinely can't
  do it.
- **State**: XState for complex machines, React Hook Form for forms, URQL for
  GraphQL state and caching.
- **GraphQL** goes through gql.tada. Fragments live beside each domain's own
  API module in `services/client/src/lib/api/` — there is no central fragments
  directory. Generated types come from Turborepo tasks, not a standalone
  `codegen` command.
- **Item types are parameterised.** Wine, beer, spirit, coffee, sake and tea
  share the components in `services/client/src/components/item-api/`. Adding a
  per-type component folder is almost always the wrong move. Adding a seventh
  type is still a multi-package change; `docs/architecture/migration-plan.md`
  §9.1 lists every file, and which ones no check will remind you about.
- **Database schema changes** are `drizzle-kit` migrations in `packages/db`,
  reviewed like any other code.

### What not to touch

- `CHANGELOG.md` — generated by release-please.
- `packages/schema/graphql-env.d.ts` and the client's `*.generated.ts` files —
  generated by the build.
- The block in `services/client/AGENTS.md` between the
  `<!-- BEGIN:nextjs-agent-rules -->` markers — `next dev` maintains it and will
  rewrite any edit, landing as an uncommitted change in whatever you were doing.
- The `nhost/` directory. It is frozen pre-migration history; nothing runs it,
  and the rollback of record is a checkout of `82450ad1`, not this tree. Don't
  build features against it.
